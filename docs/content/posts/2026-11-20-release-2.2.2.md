The Apache Flink Community is pleased to announce the second bug fix release of the Flink 2.2 series.

This release includes 74 bug fixes and improvements for Flink 2.2. The list below excludes flaky and test-only, CI and build, documentation-only, and release-tooling changes. For a complete list of all changes see [JIRA](https://issues.apache.org/jira/secure/ReleaseNote.jspa?version=12357057&projectId=12315522).

The following fixes come with release notes:

- [FLINK-39136](https://issues.apache.org/jira/browse/FLINK-39136): Upgraded the bundled google-cloud-storage library in flink-gs-fs-hadoop (2.29.1 → 2.68.0) to fix a NullPointerException on GCS 503 responses during resumable uploads that could fail checkpoints to gs://. No configuration or API changes required.
- [FLINK-40003](https://issues.apache.org/jira/browse/FLINK-40003): Fixes temporarily stale IOMetrics and accumulator on job completion listeners.
- [FLINK-40475](https://issues.apache.org/jira/browse/FLINK-40475): When all inputs of a multi-input task become idle, Flink now always emits the maximum watermark across all inputs, regardless of the order in which the inputs became idle. Watermarks of inputs resuming from idleness are also emitted promptly instead of potentially stalling. Jobs relying on the previous order-dependent behavior may observe windows and timers firing earlier, and more records treated as late when idle inputs resume with old-timestamped data.
- [FLINK-40499](https://issues.apache.org/jira/browse/FLINK-40499): When a source was idle at the moment it finished (end of a bounded input or stop-with-savepoint --drain), the final watermark was dropped and downstream event-time windows and timers did not fire. The source now marks itself active before the final watermark, so operators that implement processWatermarkStatus can see one extra ACTIVE status just before end of input.
- [FLINK-40504](https://issues.apache.org/jira/browse/FLINK-40504): Idle source outputs are now re-activated on any sign of activity, not only on an advancing watermark. A FLIP-27 source that had been announced as IDLE downstream stayed IDLE after it resumed while its watermark stayed behind the maximum already reached, so its records could be dropped as late events; the same applied when a new split was registered while the source was idle. WatermarksWithIdleness now also marks the output active again on the first record after idleness, instead of waiting for the wrapped generator to emit an advancing watermark.
- [FLINK-41280](https://issues.apache.org/jira/browse/FLINK-41280): CAST of a TIMESTAMP before 1970 to DATE, to TIME, or to a TIMESTAMP or TIMESTAMP_LTZ precision of 3 or less rounded toward 1970. For example, CAST(TIMESTAMP '1969-12-31 23:00:00' AS DATE) returned 1970-01-01. It now returns 1969-12-31. Results change for such values, also when a compiled plan is restored.

We highly recommend all users upgrade to Flink 2.2.2.
