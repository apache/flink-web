The Apache Flink Community is pleased to announce the sixth bug fix release of the Flink 1.20 series.

This release includes 46 bug fixes and improvements for Flink 1.20. The list below excludes flaky and test-only, CI and build, documentation-only, and release-tooling changes. For a complete list of all changes see [JIRA](https://issues.apache.org/jira/secure/ReleaseNote.jspa?version=12357158&projectId=12315522).

This release contains security fixes [FLINK-39146](https://issues.apache.org/jira/browse/FLINK-39146), [FLINK-39572](https://issues.apache.org/jira/browse/FLINK-39572), [FLINK-40539](https://issues.apache.org/jira/browse/FLINK-40539), [FLINK-41291](https://issues.apache.org/jira/browse/FLINK-41291); data-correctness fixes [FLINK-23758](https://issues.apache.org/jira/browse/FLINK-23758), [FLINK-33123](https://issues.apache.org/jira/browse/FLINK-33123), [FLINK-39481](https://issues.apache.org/jira/browse/FLINK-39481), [FLINK-39720](https://issues.apache.org/jira/browse/FLINK-39720), [FLINK-40335](https://issues.apache.org/jira/browse/FLINK-40335), [FLINK-40475](https://issues.apache.org/jira/browse/FLINK-40475), [FLINK-40780](https://issues.apache.org/jira/browse/FLINK-40780), [FLINK-40904](https://issues.apache.org/jira/browse/FLINK-40904), [FLINK-40959](https://issues.apache.org/jira/browse/FLINK-40959), [FLINK-41102](https://issues.apache.org/jira/browse/FLINK-41102), [FLINK-41104](https://issues.apache.org/jira/browse/FLINK-41104), [FLINK-41108](https://issues.apache.org/jira/browse/FLINK-41108), [FLINK-41196](https://issues.apache.org/jira/browse/FLINK-41196), [FLINK-41228](https://issues.apache.org/jira/browse/FLINK-41228), [FLINK-41280](https://issues.apache.org/jira/browse/FLINK-41280).

The following fixes come with release notes:

- [FLINK-40003](https://issues.apache.org/jira/browse/FLINK-40003): Fixes temporarily stale IOMetrics and accumulator on job completion listeners.
- [FLINK-40475](https://issues.apache.org/jira/browse/FLINK-40475): When all inputs of a multi-input task become idle, Flink now always emits the maximum watermark across all inputs, regardless of the order in which the inputs became idle. Watermarks of inputs resuming from idleness are also emitted promptly instead of potentially stalling. Jobs relying on the previous order-dependent behavior may observe windows and timers firing earlier, and more records treated as late when idle inputs resume with old-timestamped data.
- [FLINK-41280](https://issues.apache.org/jira/browse/FLINK-41280): CAST of a TIMESTAMP before 1970 to DATE, to TIME, or to a TIMESTAMP or TIMESTAMP_LTZ precision of 3 or less rounded toward 1970. For example, CAST(TIMESTAMP '1969-12-31 23:00:00' AS DATE) returned 1970-01-01. It now returns 1969-12-31. Results change for such values, also when a compiled plan is restored.

We highly recommend all users upgrade to Flink 1.20.6.
